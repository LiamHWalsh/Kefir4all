# AGENTS.md — guidelines for AI agents working on this repository

This file tells code-assistance agents (Claude, Copilot, etc.) how to operate
inside the Kefir4All codebase. Follow these rules for every change.

## 1. No emoji or icons in documentation

Documentation headings, commit messages, and prose must be plain ASCII text.
No emoji, pictograms, decorative Unicode, or icon-font characters.

## 2. Check for an existing well-maintained package first

Before writing any custom code:

1. Search CRAN/Bioconductor for a package that already solves the problem.
2. If one exists and is actively maintained, use it — do not re-implement.
3. Only write custom code when no suitable package exists, and document why.

## 3. Code-quality checks (every change)

Before finalising any code change, inspect it for:

- **Scientific accuracy** — does it compute what it claims to? Are p-values,
  thresholds, and statistical tests applied correctly?
- **Reusability** — can another researcher run this with different data?
- **Elegance** — is it the simplest implementation that works? Avoid
  unnecessary abstraction, indirection, or cleverness.
- **Overengineering risk** — is this doing more than the task requires?
  Extra parameters, unused code paths, premature generalisation.

## 4. Generate manual validation warnings

When a proposed change touches an output that an existing tool or script
already produces correctly, warn the user instead of silently
re-implementing. Example: "This plot is already generated by
`04_taxonomic_profiling.R` — modifying it here would bypass the existing
pipeline."

## 5. Commit hygiene

- Each commit must be a single logical change.
- Commit messages must describe what changed and why, not how.
- Never commit generated artefacts (`.jpeg`, `.pdf`, `.tar.gz`, etc.)
  unless explicitly asked.
